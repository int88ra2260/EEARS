# 效能與記憶體

環境是這次 Jest 行程，不是負載測試，沒有毫秒 SLA。輸入是合成物件。

Flag 關閉、2000 列：約 0.01 ms，回傳 null，沒有呼叫 capture。

回歸那次測得：

| 列數 | 評估列數 | 截斷 | 約略時間 |
|---|---|---|---|
| 0 | 0 | 否 | 0.13 ms |
| 20 | 20 | 否 | 1.02 ms |
| 200 | 200 | 否 | 19.81 ms |
| 500 | 200 | 是 | 37.49 ms |
| 2000 | 200 | 是 | 20.09 ms |

同一輪裡 2000 列是 20.09 ms，500 列那一次是 37.49 ms。時間沒有跟著尾端列數上升。另有一個 500 列 proxy：index 200 以後的讀取會 throw。診斷仍成功，所以 shadow 沒有掃完整個尾端，也沒有把 500 列深拷進 validator。

匯入本身仍會把整份 Excel 放進 `rows`。那是既有行為，不是 shadow 的第二份全檔拷貝。
