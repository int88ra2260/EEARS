# Phase 4K 銜接界線

本階段沒有把 validator 掛上任何路由或 service。

若下一階段要接，只適合做成成績匯入回應組好之後的非阻擋呼叫：

1. 匯入函式先維持目前的寫入、跳過與回應。品質報告失敗不得改變 `imported`、`skipped` 或資料庫列。
2. 輸入使用該次已經在記憶體中的列與跳過碼。不要為了品質報告再查學生、姓名或 email。
3. 報告與 log 只用列索引、finding code 與計數。不寫學號。
4. 既有 JSON 回應先維持原欄位。品質報告若要出現，放在不破壞舊欄位的旁路，並可整個關閉。
5. 單次掃描維持目前上限 200 列。超過時報告已有 `ROW_SCAN_TRUNCATED`，不得改成同步長交易。
6. 回退方式是不再呼叫 `evaluateBestepFileQuality`。不需要 migration。

不適合在 4K 直接做的事：用這份報告改寫 `examDate`、還原 `B2+`、把投影日當來源日、把缺席未知改成缺考、或把報告數字放進 KPI。
