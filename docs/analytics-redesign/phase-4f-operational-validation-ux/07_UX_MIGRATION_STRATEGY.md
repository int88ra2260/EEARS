# 從現有頁面移過去

起點是 `AdminAnalyticsPage` 的活動營運區。三步都保留原 API、原權限、原學期篩選與原統計結果。`englishPassRate` 不從 API 刪除。待 L3 的項目在文案上標待驗證，不寫成核定成果。

## 第 1 步：只加說明

做法：KPI 標題改成文案檔的候選名稱，hint 改成對應的母體與限制。類型表上方加一句「不要把這張表再加總成第二個總數」。學期旁顯示設定檔日期。不調整區塊順序，不顯示 `englishPassRate`。

驗收：

- 同一學期、同一帳號，四個數字與改版前相同。
- 網路請求仍是現有的 overview、名額分項、趨勢與班級排行。
- 頁面上沒有「達標率」或「活動成效」。
- 隱藏場次與違規表對帳標成待驗證。

回退：回復這一段文案。沒有資料轉換可回退。

## 第 2 步：依供給、需求、到場、例外分組

做法：把既有四張卡片放進四個小標，場次表與類型表移到問題下方。趨勢與班級排行留在原 API。仍不新增篩選。類型關鍵字若做前端過濾，只過濾表格，頭條數字不變，並在過濾器上寫「只影響表格」。

驗收：

- 篩選學期後，日期窗、四個頭條與兩張表的原始值與第 1 步相同。
- 權限不足時仍是原本的拒絕，不會看到部分母體。
- `englishPassRate` 若尚未做補充區，就繼續不顯示。

回退：回復第 1 步的直線排列。API 沒有版本可切。

## 第 3 步：在 L3 之後才改結構

做法：V-OPS-02、03、05、06 有彙總結果後，才決定待驗證標籤要留下或改成「已於某日對過資料」。仍不改 SQL。若主任要求學生人數或違規事件率，那是新指標，不在這三步裡用現有欄位頂替。補充區可以選擇顯示報名 B2 標記，標題使用文案檔，預設收合。

驗收：

- 沒有 L3 結果的項目，畫面上仍寫待驗證。
- 補充區的數字若顯示，與 API 的 `englishPassRate` 相同，且區塊標題含「報名資料」。
- 既有趨勢、班級排行、場次表仍可開啟。

回退：隱藏新的分組標題與補充區，回到第 2 步或第 1 步。因為沒有改 API，回退只涉及前端版面。

## 不做的事

- 不刪除活動趨勢、出席趨勢或班級排行。
- 不把名額分項 API 拆掉或合併成新端點。
- 不因文案變更而重算百分比。
- 不把待驗證的違規狀態比標成「違規事件已核對」。
