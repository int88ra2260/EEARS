# 效能觀察

環境是這次 Jest 行程，不是負載測試，也沒有訂毫秒 SLA。輸入是合成物件，不是 Excel。2000 列的案例確認 validator 輸入只有前 200 列，後面的列沒有被深拷進報告。

Flag 關閉、2000 列：約 0.02 ms，回傳 null。

Flag 開啟：

| 列數 | 評估列數 | 截斷 | 約略時間 |
|---|---|---|---|
| 0 | 0 | 否 | 0.12 ms |
| 20 | 20 | 否 | 0.98 ms |
| 200 | 200 | 否 | 19.5 ms |
| 500 | 200 | 是 | 19.4 ms |
| 2000 | 200 | 是 | 19.5 ms |

500 與 2000 的時間停在 200 列附近，沒有跟著總列數上升。這次匯入本來就會把整份 Excel 放進 `rows`；shadow 沒有再做第二次全檔拷貝。投影比對沒有跑，因為投影集合是 `not_observed`，所以這條路徑沒有對全部列做兩兩配對。

四技能仍依 validator 既有規則，只對前綴展開。Shadow 例外時回一個小的 `shadow_error` 物件，不保留原始列。
