# 垂直切片候選

比較依據是現役程式，不是哪一個看起來比較小。

| 準則 | A 報名與到考 | B 單次技能表現 | C 成績匯入品質 |
|---|---|---|---|
| 業務價值 | 行政要看報名與缺考。班級頁已經有單班數字 | 主任會想看四科技能。現役中心分布入口未掛載 | 先回答這份成績能不能被當成一次測驗。這是 A、B 共用的前提 |
| 來源清楚度 | 報名表與出席表清楚，但場次表不在匯入路徑 | 成績檔清楚，投影到 exam 與 et 不清楚 | 成績列、跳過原因、batch id 都在匯入程式 |
| 指標清楚度 | 列數、人數、項目數、班級分母已經不同 | 技能 observation 與學生通過率容易被看成同一個數 | 可先報列數、缺日期、缺技能、跳過，不必合成通過率 |
| 時間清楚度 | 出席有匯入日；報名只有學期 | 成績考試日是 null；同步會另造日期 | 這個差異正是本候選要標出來的 |
| 既有 API | 班級 overview 可讀，但是班級範圍 | 沒有現役中心成績分布 API | 匯入回應有計數，沒有品質查詢。適合 shadow，不必先改 API |
| 契約 | 報名 B2 標記已有 metric。到考率沒有中心 id | `bestep.file.skill_*` 存在，但 D1 未決 | `TC-BESTEP-FILE-SEMESTER` 與 observation adapter 可直接用於合成列 |
| 決策依賴 | 名額不存在。缺考未知與 false 要先分開 | D1、加號、來源優先權都會擋官方解讀 | 可以在不決定 B2 政策下記品質旗標 |
| 可測試 | 班級函式已有合成測試 | 四技能與加號已有契約測試 | 同一批測試可再加缺日期與跳過，不必連資料庫 |
| 可回退 | 改班級頁會碰到現役教師流程 | 新分布頁容易被當成正式達標 | shadow 不掛進回應即可停 |
| L3 | 中心人數仍要真實列才能對外 | 分布形狀要真實列 | 真實 null 比例與跳過率仍要 L3，但合成契約可先做 |

## 選擇

Phase 4J 選 **C**，pilot id：`bestep-file-quality`。

A 不是因為比較難才被放下。它的班級到考率已經在 `computeClassBestepExportSummary` 算出來，分母是班級本國生的報考項目。中心場次名額沒有欄位。先做 A 的中心版，會把現成的班級算法放大成另一個母體。

B 的四科欄位齊全，但 `examDate` 被匯入清空，加號已不在欄位裡，KPI 又讀另一張表。現在做技能分布，畫面會像一次正式測驗的達標結果。

C 用既有 observation 回答：這一檔有多少列、多少缺日期、多少四科不齊、哪些學號因為沒有 success 報名而被跳過、同步出去的日期是不是來源日期。官方使用與因果宣稱維持關閉。
