# 發現、解釋、檢視、行動

合成情境使用瀏覽器測試的契約回應，不是正式資料庫。

## 發現

管理者由 `/admin/analytics` 點「活動營運總覽」，進入 `/admin/analytics/overview`。

學期選擇器送出既有 `semester`。非 `114-1` 的合成回應中，總覽 `totalReservations` 為 48，分項 `items[0].eventType` 為 English Table、`totalReservations` 為 48。

觀察第一句寫所選學期與活動日期。第二句寫：預約筆數主要出現在「English Table」，共 48 筆預約列。

## 解釋

同一句寫明這是預約列，不是不重複學生人數。畫面不出現「供給不足」「成效最好」「造成能力」「增開」。

`attendanceRate` 40 顯示為 40.0%，並說明分母是預約列、沒有依類型拆開。`violationRate` 1 顯示為 1.0%，並說明時間是活動日期，不是違規登錄日。

若出席或違規不是有限數值，句子改為沒有數值、不另算比例。若各類型都沒有預約筆數，句子改為資料不足。

## 檢視

KPI 卡仍顯示 API 原值。說明按鈕展開既有定義：名稱、統計單位、母體、時間欄位、限制。空值是「—」，數值 0 是 `0` 或 `0.0%`。

B2 標記留在報名補充區，文案維持報名表 `hasCEFRB2`，不能據此認定活動提升能力。

## 行動

具有活動列表權限者看到「開啟活動列表」，`href` 為 `/admin/operations`，沒有查詢字串。提示寫：活動列表不會套用此頁的學期或活動類型，請在該頁自行篩選。

切到 `114-1` 後，同一條觀察改為 7 筆預約列，上一筆 48 不再留下。總覽 500 時只留錯誤警示，觀察區塊不出現。
