# 本次實際改善

`/admin/analytics/overview` 仍是既有活動營運總覽。本階段沒有新增 KPI、沒有新 API、沒有改 SQL。

管理者現在可以在同一頁完成一條操作：

1. 從 `/admin/analytics` 進入活動營運總覽。
2. 讀「營運觀察」：哪一類活動的預約列較多、全頁簽到率與違規狀態比是什麼、母體與活動日期是什麼。
3. 依權限開啟既有管理頁。連結只有路徑，並寫明該頁不會套用這裡的學期或活動類型。

觀察只在總覽載入成功後出現。載入中先清空上一筆結果。API 錯誤顯示警示，不顯示觀察，也不把錯誤寫成 0。

B2 標記仍只在報名補充區。預約筆數的說明維持「預約列」，不是不重複學生人數。分項表沒有各類型出席數，所以觀察不另算類型出席率。

程式在 `feature/analytics-operations-experience`。基準是 Phase 6B.2 commit `0ca8867a159b04d21d73a9fd6173142fe4916d19`。本提交只收斂這條營運觀察流程。
