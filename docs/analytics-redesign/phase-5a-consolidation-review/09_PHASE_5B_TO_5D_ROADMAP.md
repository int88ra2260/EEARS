# Phase 5B–5D

本階段沒有實作這三步。順序依本次證據，而不是預先假設必須先改公式。

## Phase 5B — 整合與回歸

目的：把已通過工程與瀏覽器驗收、且不改 KPI 的提交準備好進入整合分支。

範圍：

- 取得發布負責人同意後，快轉本分支 16 個提交。本文件不執行。
- 在 Node 20 重跑 `06` 的命令。
- 確認三個 Shadow 環境變數在目標環境未設定。
- 不修改通過率、不合併 Shadow 框架、不改 Metric 數量。

完成條件：整合分支包含 `1a00599`，回歸通過，正式回應在旗標關閉時與合併前一致。

不包含：F-BESTEP-01 公式、L3、生產部署。

## Phase 5C — 政策與 L3 準備

目的：把已寫好的決策包交給負責人，並準備受控唯讀驗證。不要在未核准時跑正式庫。

優先決策：F-BESTEP-01 / DG-BESTEP-03、D11、D10、DG-BESTEP-01、DG-BESTEP-04。其餘 D1–D9 可同包送出，但不阻擋出席顯示。

L3 只規劃查詢與授權。查詢不得把 `1970-01-01` 當成考試日，不得把 query semester 當成資料日，不得把不同來源併成一次實測。

完成條件：每個要改公式的項目有書面選項。沒有書面選項就維持現況。

## Phase 5D — Staging 候選

條件：5B 已在整合分支，出席與活動文案的顯示範圍已核准，Shadow 在 staging 保持關閉，除非另有診斷授權。

官方達標報告不進入這個候選。它要等 5C 的政策與 L3。

Staging 通過仍不是 Production。Production 另需發布負責人核准與部署紀錄。

## 依賴

5D 的顯示候選依賴 5B。5D 的官方數字依賴 5C。5C 不依賴 5B 的合併，決策可以先做；公式修改則必須在決策之後另開實作，不能塞進 5A。
