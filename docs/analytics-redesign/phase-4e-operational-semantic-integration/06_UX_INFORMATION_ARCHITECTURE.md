# 營運總覽之後可以怎麼呈現

這份只供下一次改畫面時使用。這次沒有改 React、路由或選單。

## 適合留在活動營運總覽

這三個已經有對應指標，而且頁面正在顯示：

- 總預約數：預約列，不是學生人數。現有提示寫的是筆數，方向對。
- 名額使用率：預約列除以區間內全部場次名額。應一併說明零預約場次仍在分母。
- 出席率：已簽到列除以預約列。應避免被讀成「有多少學生出席」。

違規率頁面也有顯示。公式看得到，但是列舉狀態，不是違規資料表，而且還沒有正式指標。可以留在營運頁，標成預約列上的違規狀態比例，先不要寫成獨立的違規管理成果。

## 不該放在同一組營運績效

`englishPassRate` 是報名表的 B2 標記。它和預約、簽到、名額沒有列級關聯，時間也是檔案學期而不是活動日。營運頁現在沒有畫它，應維持這樣。若還要給人看，放到報名或培力補充區，並寫明它不是活動後的英語能力。

## 使用者需要看得到的查詢上下文

現在回應裡已經有材料，畫面還沒有把它講清楚：

- 114-2 實際用的活動日是 `2026-02-01` 到 `2026-07-31`，含最後一天。這組日期在 `capacityBreakdown.range`，不是另一個隱藏規則。
- 母體是全中心活動，不是某個班級名單。
- 總預約是列數。同一人多場會多計。
- 出席率的分母含未簽到與已登記違規。它不是「至少簽到一次的學生 / 有預約的學生」。

## 先不要當成已定口徑

- 違規率與 `event_violations` 的關係。
- 頂層名額率與分項 summary 是否每次都相同。這是兩段 SQL。
- 含尾日 CAST 與半開區間在資料庫上是否同一批活動。
- 取消預約後列還在不在。總覽 SQL 沒有處理 `cancellationCode`。
- `hiddenFromStudents` 的場次目前仍在名額裡。

名額分項表目前主要來自另一支 API，總覽內的 `capacityBreakdown` 是同一組函式的嵌套結果，也是前端正規化的後援。兩條路徑的語意應維持同一套卡片，但這次沒有改那支獨立路由。
