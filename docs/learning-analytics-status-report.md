## 0. 執行摘要（給主管）

學習成效分析把「英檢成績」與「課程／活動參與」放在同一套分析快照上，協助中心觀察：誰有可計算的進步、群體差異、資源／細項與進步的**關聯趨勢**。

**一句話定位：** 這是「英語中心營運與能力觀察台」，不是「準實驗成效證明機」。

2026-09 完成一輪產品／資料語意稽核與修復後，現況可概括為：

| 層面 | 評估 |
|------|------|
| 資料底層 | 相對紮實（學習歷程 analytic 快照、重建管線、非因果旗標） |
| 描述統計 | 可用（總覽、群體、細項、技能、原始資料） |
| 準因果估計（配對／IPW／AIPW） | 有實作，但僅適作進階對照；小樣本已隱藏 |
| 啟發式「通過機會」 | 實驗功能，不可作輔導優先序或認證預測 |
| 主要風險（已修） | 學期篩選誤導、資料版本隱形、原始分與 GSE 同軸混畫 |

**對外／對內簡報請維持：**「觀察到與參與相關的成長趨勢」；避免「證實活動造成進步」「保證通過」。

## 1. 模組目的與非目的

### 1.1 目的

1. 彙整英檢前後測與學習資源參與，計算可解釋的成長指標（GSE 實際／校正成長）。
2. 依群體（系所、入學年度、起點能力等）做描述性比較。
3. 依資源類型、課程／教師／活動細項，觀察參與者與成長的關聯。
4. 提供原始資料預覽／匯出與分析紀錄固化，供會議重現。

### 1.2 非目的（明確不做或不得宣稱）

- 不證明某課程、教師或活動「造成」能力提升。
- 不作教師績效排名對外公布。
- GSE 不是官方認證分數；CEFR／B2 認證另依名冊規則。
- 啟發式通過分層不是正式預測模型。

## 2. 系統架構概要

### 2.1 資料流

```
英檢／修課／活動／基線
        ↓
學習歷程重建 → lj_analytic_students / lj_analytic_exams（+ 事件）
        ↓
LVA 服務層（篩選、GSE 換算、成長、資源估計、細項彙總）
        ↓
後台 admin/learning-analytics 各子頁
```

### 2.2 與學習歷程（LJ v3）關係

| 角色 | 說明 |
|------|------|
| LJ | 學生歷程主檔、維運重建、學期營運總覽 |
| LVA | 讀取 analytic 投影做成效觀察；維運入口仍在 LJ Operations |
| 微學習 trace | 獨立時間窗（近 30／90 天），與 LA 篩選不同宇宙 |

雙入口（LVA 學習軌跡 ↔ LJ 學生檔）資料同源，但產品邊界需在 UI 上持續標清。

### 2.3 權限（概念）

- 檢視成效分析、匯出、執行 model run、模組設定等分權限控制。
- 教師角色於細項分析可限制為僅見自己授課列（self-scope）。

## 3. 後台功能現況（依子頁）

路徑前綴：`/admin/learning-analytics/`

| 子頁 | 路徑 | 現況定位 | 篩選語意 |
|------|------|----------|----------|
| 中心總覽 | `overview` | 快照能力摘要 +（可選）學期認證區；含微學習／漏斗面板 | 學期主要影響認證區塊；其餘依快照與學生條件 |
| 群體分析 | `cohorts` | 依系所／入學年等分組比較 | 完整學生群體篩選適用 |
| 細項分析 | `offerings` | 課程／教師／活動／資源類別描述統計 | **僅學期＋資料版本**（不適用系所等群體篩選） |
| 資源效益 | `resources` | 描述表為主；進階估計（配對／IPW／AIPW）為實驗區 | 群體篩選適用；進階列需樣本 ≥10 |
| 技能成長 | `skills` | GSE 實際 vs 校正成長（同尺） | 群體篩選適用 |
| 學習軌跡 | `students/:id` | 個人時間線與建議（實驗） | 間接帶入快照／URL |
| 原始資料 | `raw-data` | 預覽／匯出底層摘要 | 群體篩選適用 |
| 進階分析 | `insights` | 散佈、趨勢、熱圖；啟發式分層為實驗 | 部分圖不受系所篩選（如固定學期 B2 趨勢） |
| 分析紀錄 | `model-runs` | 固化當下篩選結果 | 篩選僅用於「存新紀錄」 |
| 模組設定 | `settings` | LVA 參數、資源技能設定檔等 | 無分析篩選列 |

頁首統一聲明：「數字用來比較趨勢，不是保證參加就進步。」

## 4. 核心指標與方法（白話）

### 4.1 能力與成長

| 指標 | 說明 | 解讀提醒 |
|------|------|----------|
| **GSE** | 跨英檢換算的能力尺（約 10–90，對齊 CEFR） | 分析用尺，非官方認證分 |
| **GSE 實際成長** | 後測 GSE − 前測 GSE | 未扣「本來就會進步」 |
| **GSE 校正成長** | 實際 − 同背景預期（回歸／分組模型） | 適合作群體比較；仍非因果 |
| **工具原始分進步** | 同測驗卷面分數差（如 TOEIC +35） | **不可與 GSE 同軸比較** |
| **資料完整度** | high／medium／low 等 | 可信度標籤，不是成績好壞 |

### 4.2 資源進階估計（觀察性）

| 方法 | 白話 | 現況姿態 |
|------|------|----------|
| 背景相近配對 | 找程度／系所相近但未參加者比較 | 進階區；樣本 &lt;10 隱藏 |
| IPW 加權 | 依「誰比較可能參加」加權再比 | 同上 |
| AIPW 雙重穩健 | 同時校正參與與結果模型 | 同上；方向一致才較值得討論 |

### 4.3 樣本門檻（勿混淆）

| 門檻 | 用途 | 典型值 |
|------|------|--------|
| UI 顯示／遮蔽 | 細項平均值、資源進階估計列 | **10**（`MIN_GROWTH_SAMPLE`／`LA_MIN_DISPLAY_SAMPLE`） |
| `evidenceLevel: medium` | 資料完整度標籤 | 約 **30**（或部分路徑 50） |
| 算法回退 | OLS／logistic 不穩時退回較簡算法 | 見方法對照文件 |

「標籤是 medium」≠「可以放心對外宣傳」。

## 5. 細項分析（Offerings）專章

### 5.1 解決的問題

既有 LVA 多以「學生」或「資源大類」為單位；細項頁回答：

- 某門課（課名＋教師）修過幾人、幾人可算成長、進步如何？
- 某教師該學期／跨學期彙總如何？
- 某一場活動出席者的成長覆蓋如何？

### 5.2 維度與規則

- 維度：課程、教師、個別活動、資源類別。
- 歸因：描述性成員歸因（學生曾參與該細項且有前後測則納入）；同一學生可計入多列。
- 隱私：可計算成長 &lt;10 人遮蔽平均進步、分布、方向人數與進步率。
- 列層指標：進步／持平／退步人數、平均＋中位／Q1–Q3、極端值警示；同測以原始分為主、GSE 為輔（contract `offerings.v4`）。
- GSE 錨點稽核：`docs/learning-analytics-gse-anchor-audit.md`（培力已依 CEFR↔GSE 帶對齊；同測仍建議對照原始分）。
- 匯出：Excel（需匯出權限）；明示非因果。

### 5.3 篩選設計（重要）

細項頁分析主體是「課／師／場次」，**不適用**完整學生群體篩選列；僅保留學期與（多版本時）資料版本。此點與總覽／群體／資源頁不同，屬刻意產品決策。

## 6. 2026-09 稽核發現與修復

### 6.1 主要問題（修復前）

1. **學期篩選語意破口**：UI 顯示已套用學期，但多數學生主指標 API 不理學期；易誤讀為「本學期成效」。同頁還存在「快照累積 B2」與「學期名冊認證率」兩套定義。
2. **資料版本幾乎隱形**：自動選版、URL／篩選列常不顯示；多版本時有錯版風險。
3. **技能頁量尺混畫**：「實際進步」曾用工具原始分、「校正後」用 GSE，同軸並畫；說明文還寫已換成同一把尺。
4. **進階功能過強包裝**：通過機會／優先投入口吻、小樣本仍出準因果數字、微學習面板看似同一篩選宇宙。

### 6.2 已完成修復（P0 → P2）

| 優先 | 內容 | 狀態 |
|------|------|------|
| P0 | 學期語意標示與預設策略；DataHealth 顯示版本；多版本可選；技能圖改 GSE 同尺 | 完成 |
| P1 | 資源進階估計小樣本隱藏；Insights 啟發式降權／收合；微學習／Trace 標「不受上方篩選」 | 完成 |
| P2 | 門檻敘事統一、PRD／方法／主管簡讀文件更新、殘餘誤導文案收斂 | 完成 |

### 6.3 修復後仍應遵守的使用規範

- 總覽上方「B2 達標率（快照累積）」與下方「學期認證率」不可直接互比。
- 資源頁「平均原始分進步」跨英檢工具不宜直接互比。
- 進階分析啟發式分層僅供內部探索。
- 微學習／推薦漏斗不受 LA 篩選；解讀時分開說明。

## 7. 產品定位與可說／不可說

### 7.1 建議定位

EEARS 成效分析 = **營運真實 + 能力觀察 + 分層對照**：

1. 量覆蓋（誰能算成長、誰缺重測）
2. 看轉移（CEFR／技能分布變化）
3. 對照分層（系所、起點、時數、細項）
4. 導出缺口（接到輔導／匯出）

### 7.2 建議用語

- 「觀察到與資源參與相關的成長趨勢」
- 「修正成長高於同背景預期」
- 「三種估計方向一致，值得持續追蹤」
- 「資料完整度提升後估計較穩」

### 7.3 避免用語

- 「證實活動造成學生進步」
- 「保證參加就能提升 GSE／CEFR」
- 「已完成因果驗證／準實驗證明」
- 「GSE 等於官方認證成績」
- 「通過機會 ≥65%，應優先投入輔導」

## 8. 後續可落地方向（建議 backlog）

以下依「現有資料能否算、主管能否一句話講清楚」排序，細節見內部發想稿。

### 8.1 三種檢視模式（建議產品分區）

| 模式 | 問題 | 時間範圍 |
|------|------|----------|
| A. 學期營運 | 名冊進度、重測、B2 缺口 | 單一學期（真篩選） |
| B. 能力觀察 | 前後測進步分布、系所／起點差 | 分析快照 |
| C. 資源／細項對照 | 課／活動參與者成長覆蓋 | 學期 + offering |

### 8.2 優先實作候補

1. 總覽明確分區：學期營運 vs 快照能力（含重測漏斗）
2. CEFR 轉移矩陣 + **同工具**原始分進步圖
3. 成長分位桶（取代過度依賴單一平均）
4. 認證／重測缺口匯出
5. 弱技能 × 曝光象限
6. Model run KPI 對照板

準因果與通過預測維持進階／實驗，不擴成主路徑。

## 10. 結論

1. **資料與描述統計已具備營運觀察價值**；2026-09 修復後，學期／版本／量尺等「看起來對齊、其實錯位」的高風險誤導已明顯下降。
2. **準因果與啟發式通過分不應再當主 KPI**；適合作進階交叉檢查或實驗探索。
3. **下一步應把產品做成「一頁一問題」**：學期營運、能力觀察、細項對照分開，並強化覆蓋率、轉移矩陣與缺口匯出等可行動指標。
4. 任何對外簡報，請以本報告第 0、7 節語氣為準。
